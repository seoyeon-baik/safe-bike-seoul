Next.js + TypeScript 기반 지도 라이딩 UI 프로토타입입니다.

```bash
npm install
npm run dev
```

http://localhost:3000 에 접속합니다.

## 카카오맵 설정

1. `.env.example`을 복사해 프로젝트 루트에 `.env.local`을 만듭니다.
2. `NEXT_PUBLIC_KAKAO_MAP_APP_KEY`에 Kakao Developers의 **JavaScript 키**를 입력합니다.
3. 해당 키의 JavaScript SDK 도메인에 `http://localhost:3000` 및 필요한 경우 `http://127.0.0.1:3000`을 등록하고 카카오맵 사용 설정을 확인합니다.
4. 개발 서버를 재시작합니다. NEXT_PUBLIC 변수는 브라우저에 공개되므로 서버용 비밀 키를 넣지 마세요.

공식 가이드: https://apis.map.kakao.com/web/guide/

키가 없거나 SDK 로드가 실패하면 개념도가 표시됩니다. SDK가 로드되면 카카오맵 위에 서울시 API의 실제 따릉이 위치·대여 수량, 공식 API에서 성공한 자전거 경로, 한국도로교통공단의 과거 사고다발지역 폴리곤·중심점을 표시합니다. 개념도에는 대여소·사고 마커나 경로선을 그리지 않습니다.

## 동작 범위

- 장소 검색: `/api/places`의 카카오 응답에서 검색/선택. 방향키·Enter·Escape 지원, 입력 지연·취소·인증 오류·빈 결과·재검색 처리. 초기 출발/목적지는 기본 위치이며 검색 결과를 가상 목록으로 대체하지 않습니다.
- 주변 검색 기준 장소와 목적지 선택·교환, 실제 조회된 가장 가까운 대여 가능 대여소 기본 선택 및 공식 경로 조회. 지도·목록에서 출발 대여소를 변경할 수 있습니다.
- 카카오 공식 자전거도로 우선·최단 경로 비교, 대여소/과거 사고지역 레이어 전환.
- 실제 따릉이 대여소 지도 마커·목록 선택, 이용 가능 자전거 수 확인.
- 선택한 출발지 기준 주변 대여소 직선거리순 검색, 반경·이름·대여 가능 필터.
- 60초 자동 갱신, 재조회, 로딩·연결 설정 누락·조회 실패·빈 결과 상태 표시.
- 과거 자전거 사고다발지역 카드: 기준연도·사고건수·사망/중상자수, 공식 경로 근접 지역 강조, 연도/근접거리 필터.
- 출발지 위경도 → 기상청 5km 격자 변환, 같은 예보시각의 예보기온·강수확률 표시, 발표/예보/조회 시각 구분.

**따릉이는 실제 서울시 bikeList API만 사용합니다. 가상 대여소·수량 데이터는 제거했습니다.** 자전거 경로는 카카오 공식 REST API 성공 응답만 표시합니다. 거리·소요시간은 해당 응답값을 사용하며 기존 가상 경로·고정 수치는 제거했습니다. 과거 사고다발지역은 한국도로교통공단 API만 사용하며 가상 사고정보는 제거했습니다. 날씨는 기상청 단기예보의 실제 응답만 사용합니다. 장소 검색 화면도 API에 연결했습니다. 명시적으로 API_DATA_MODE=demo를 선택했을 때만 예시 검색 모드임을 표시합니다. API 키가 없으면 대여소는 오류 안내와 빈 목록을 표시하고 예시 데이터로 대체하지 않습니다.

따릉이 조회: `src/lib/server/seoul-stations.ts` / 거리 계산: `src/lib/stations.ts` / 클라이언트 연동: `src/hooks/use-stations.ts` / 나머지 예시 데이터: `src/lib/demo-data.ts` / SDK 및 개념도: `src/components/bike-map.tsx`

## 통합 라이딩 화면과 비교 기준

`/` 한 페이지에서 출발 대여소·목적지 선택, 따릉이, 두 자전거 경로, 과거 사고다발지역, 출발지 날씨를 함께 봅니다. 상단 통합 현황은 4개 정보의 수신 여부·출처·수집시각을 보여 주고, 날씨는 발표/예보시각도 별도로 표시합니다. 같은 날씨 상태를 통합 현황과 상세 카드가 공유하므로 중복 조회하지 않습니다.

경로 비교표에는 자전거도로 우선/최단 경로의 거리, 예상 소요시간, 선택 연도의 주변 사고다발지역 수를 나란히 표시합니다. 같은 출발 대여소·목적지, 같은 사고자료, 같은 100/200/500m 근접 기준으로 계산합니다. 경로 선택을 바꾸면 지도와 사고지역 강조도 함께 바뀝니다.

- 비교값은 과거 **사고지역의 고유 ID 개수(곳)**입니다. 사고건수·사상자수를 합하지 않고, 같은 ID를 중복 계산하지 않습니다. 같은 사고지역이 두 경로에 각각 포함될 수 있습니다.
- 조회 중/실패/미조회는 `0곳`으로 표시하지 않습니다. 성공적으로 받은 빈 사고자료만 0곳이며, 경로나 사고자료가 없으면 비교값은 미확인입니다. 경로 API가 실패하면 임의 경로를 만들지 않습니다.
- 사고영역이 없어 중심점으로 비교한 지역 수와 좌표 오류로 제외된 지역이 있으면 그 한계를 표시합니다. 지도 표시 토글이나 근접 지역만 보기 필터는 비교표의 원본 데이터 범위를 바꾸지 않습니다.
- 자료별 시각을 통합시각 하나로 덮어쓰지 않습니다. 따릉이 개별 측정시각은 API에서 제공하지 않으므로 서버 수집시각으로 표시하고, 사고자료는 사고 기준연도와 서버 수집시각을 구분합니다. 날씨 발표/예보/수집시각도 각각 표시합니다. 표시는 모두 한국시간(KST)입니다.
- 사고지역 수는 안전성 점수·추천 순위가 아니며, 실제 통과·현재 위험도·안전을 보장하지 않습니다. 짧은 경로나 사고지역이 적은 경로에 안전 등급/우승 배지를 붙이지 않습니다.

핵심 비교 계산: `src/lib/route-comparison.ts` / 비교표: `src/components/route-comparison.tsx` / 출처·시각 통합 카드: `src/components/ride-overview.tsx`.

## 서버 API와 인증키 관리

프로젝트 루트의 `.env.local`에 설정합니다. 빈 템플릿은 `.env.example`에 있으며 실제 키는 직접 입력해야 합니다. 상위 폴더의 기존 `.env`는 변경하거나 복사하지 않습니다. Next.js는 `safe-bike-seoul/` 루트의 환경변수를 읽습니다.

```dotenv
API_DATA_MODE=demo
SEOUL_API_KEY=
DATA_GO_KR_SERVICE_KEY=
TAAS_API_KEY=
KAKAO_REST_API_KEY=
NEXT_PUBLIC_KAKAO_MAP_APP_KEY=
```

- `API_DATA_MODE=demo` (기본): 장소 검색 API만 예시 데이터를 반환합니다. **따릉이·자전거 경로·과거 사고·날씨 API는 이 값과 무관하게 실제 API만 사용합니다.**
- `API_DATA_MODE=live`: 장소 검색 API도 실제 호출합니다. 해당 키가 없으면 503을 반환하며 예시 데이터로 몰래 대체하지 않습니다.
- `SEOUL_API_KEY`: 서울 열린데이터광장 인증키.
- `DATA_GO_KR_SERVICE_KEY`: 기상청 단기예보 조회서비스 활용 신청 후 발급받은 **일반 인증키(Decoding)**. 서버에서 한 번만 URL 인코딩합니다.
- `TAAS_API_KEY`: 자전거 교통사고 다발지역 API의 공공데이터포털 일반 인증키(Decoding). 비어 있으면 `DATA_GO_KR_SERVICE_KEY`를 사용합니다. 기상청 키를 이미 보유해도 사고 API에 대한 별도 활용신청/승인이 필요합니다. 공단 자체 포털용 authKey와 공공데이터포털 serviceKey를 혼용하지 마세요.
- `KAKAO_REST_API_KEY`: 카카오 로컬 검색 및 공식 자전거 경로 조회용 REST API 키. JavaScript 키/어드민 키와 구분합니다.
- `NEXT_PUBLIC_KAKAO_MAP_APP_KEY`: 지도 SDK를 위해 브라우저에 공개되는 JavaScript 키. 비밀 키를 여기에 넣으면 안 됩니다. 카카오에 허용 도메인을 등록하세요.

서버 키는 `src/lib/server/`에서만 읽으며 `server-only` 경계가 클라이언트 import를 차단합니다. `next.config.ts`의 `env` 옵션으로 키를 내보내지 않습니다. 클라이언트에서는 외부 API 대신 아래 같은 동일 출처 API를 호출하면 됩니다.

```ts
const response = await fetch('/api/places?query=' + encodeURIComponent('여의나루'));
const payload = await response.json();
// payload.data / payload.meta.isDemo / payload.meta.source
```

화면의 따릉이 영역은 `/api/stations`, 경로 비교는 `/api/routes`, 과거 사고 영역은 `/api/accidents`, 날씨 카드는 `/api/weather`에 연결되어 실제 데이터만 사용합니다. `API_DATA_MODE`는 장소 검색 백엔드만 전환하며, 장소 선택 화면은 API 응답의 실제/예시 모드를 명시합니다. 출발지를 선택하면 경로 검색 버튼을 누르기 전에도 주변 대여소를 다시 조회합니다. 거리순 정렬 기준을 카드에 표시합니다.

| GET API | 매개변수 | 내용 |
| --- | --- | --- |
| `/api/stations` | `lat=37.5271&lng=126.9328&radius=2000&limit=30&availableOnly=0&query=` | 항상 실제 따릉이. 출발지 주변 반경 내 대여소를 직선거리순으로 반환합니다. lat/lng는 함께 입력하며 생략 시 여의나루역 좌표를 사용합니다. radius 100~10000m, limit 1~100, availableOnly 0/1, 이름 검색어 80자 이하. 이전 start 매개변수는 지원하지 않습니다. |
| `/api/places` | `query=여의나루&page=1` | 1~80자 검색어, page 1~45. 실제 모드는 서울 주변 사각 영역으로 검색 범위를 제한합니다. |
| `/api/weather` | `lat=37.5271&lng=126.9328` | 출발지 위경도 필수. 서버에서 기상청 DFS 격자로 변환 후 단기예보 조회. 날씨도 항상 `isDemo: false`. 이전 nx/ny 직접 입력은 지원하지 않습니다. |
| `/api/accidents` | `year=2025` | 서울 25개 구의 자전거 사고다발지역 전체 조회. 2012~2025, 생략 시 공식 안내 최근 제공연도 2025. 폴리곤·중심점·사고/사상자 통계 반환. 항상 `isDemo: false`. |
| `/api/routes` | `stationId=ST-실제ID&endLat=37.5103&endLng=126.9959` | 선택한 실제 따릉이 대여소에서 목적지까지 BIKE_ONLY·SHORTEST를 함께 조회. 출발 좌표는 서울시 목록에서 서버가 확인합니다. 모든 성공 응답은 `isDemo: false`. 이전 from/to 예시 ID는 지원하지 않습니다. |

응답은 `{ data, meta: { source, isDemo, fetchedAt, ... } }` 형식입니다. 날씨는 같은 예보시각의 `temperatureC`(TMP)와 `precipitationProbability`(POP)를 반환합니다. 발표시각은 `baseDate`/`baseTime` 및 `publishedAt`, 예보 대상시각은 `fcstDate`/`fcstTime` 및 `forecastAt`, 서버 조회시각은 `meta.fetchedAt`입니다. 예보를 현재 관측값으로 표시하지 않습니다.

잘못된 입력은 400, 미설정 키는 503, 외부 API 오류는 502, 외부 요청 타임아웃은 504입니다(일반 조회 8초, 카카오 경로 요청 각 10초). 카카오의 경로 없음 응답은 422, 삭제된 대여소는 404입니다. 응답에는 `Cache-Control: no-store`를 적용합니다. 오류 본문·요청 URL·인증 헤더·환경변수 원문은 로그나 브라우저 응답으로 전달하지 않습니다. 외부 API는 고정된 주소만 호출하며 임의 URL 프록시와 리다이렉트를 허용하지 않습니다.

서울시 공식 따릉이 호출 주소는 현재 HTTP이며 인증키가 경로에 들어갑니다. 브라우저로 이 주소를 전달하지 않지만, 서버와 서울시 사이의 전송 자체가 TLS로 암호화되는 것은 아닙니다. 카카오·기상청은 HTTPS로 호출합니다.

### 따릉이 조회 방식

서버는 한 번에 최대 1000개씩 `bikeList/1/1000`, `bikeList/1001/2000` 순서로 조회합니다. 마지막 짧은 페이지 또는 `INFO-200`까지 전체 페이지를 읽은 뒤 거리순 정렬합니다. `list_total_count`가 페이지의 건수일 수 있어 도시 전체 건수로 가정하지 않습니다. 일부 페이지 조회가 실패하면 부분 목록을 가까운 순위로 반환하지 않습니다. 최대 20페이지와 총 조회 시간 제한을 둡니다.

위경도가 없는 대여소는 지도에 표시하지 않고 `meta.skipped`에 집계합니다. 같은 대여소 ID는 합치며, 자전거 0대는 기본적으로 회색 마커와 목록에 남습니다. 실제 주차 자전거 수가 거치대 수를 넘는 경우도 그대로 표시합니다.

전체 조회 결과는 서버 프로세스 메모리에 최대 60초 저장하고 동시 요청을 합칩니다. 키·URL을 디스크 캐시에 저장하지 않습니다. 화면도 60초 간격으로 재조회하며 수동 재조회는 유효한 서버 캐시를 재사용할 수 있습니다. `meta.fetchedAt`은 서울시 응답을 수집한 시각이며, 모든 대여소의 동시 관측시각을 의미하지 않습니다. 페이지를 순차 수집하는 동안 대여 수량이 달라질 수 있습니다. 만료 후 조회에 실패하면 오래된 결과를 최신값으로 대체하지 않습니다.

`meta.total`은 유효 좌표가 있는 전체 대여소 수, `meta.matched`는 필터 후 반경 내 전체 수입니다. 화면에서는 가까운 30개를 표시합니다. 응답의 `distanceMeters`는 하버사인 공식으로 계산한 직선거리이며 도보·자전거 경로 길이가 아닙니다.

실제 화면을 보려면 `.env.local`의 `SEOUL_API_KEY`와 `NEXT_PUBLIC_KAKAO_MAP_APP_KEY`를 설정한 뒤 서버를 재시작하세요. 서버 키는 계속 브라우저로 전달하지 않습니다. 카카오 지도 키가 없으면 실제 대여소는 목록·위경도로 확인할 수 있고 지도 마커는 지도 SDK 연결 후 표시됩니다.

### 공식 자전거 경로 및 권한 검사

공식 명세: [카카오맵 자전거 경로 REST API](https://developers.kakao.com/docs/ko/kakaomap/rest-api#routing-bicycle).

- GET `https://dapi.kakao.com/v2/routing/bicycle`
- 인증 헤더: `Authorization: KakaoAK {REST_API_KEY}` (서버에서만 사용)
- 탐색 옵션: `route_mode=BIKE_ONLY`(자전거도로 우선), `route_mode=SHORTEST`(최단 경로)
- 좌표: `start_x/end_x`는 경도, `start_y/end_y`는 위도. 입출력은 WGS84.
- 서울시에서 확인한 실제 대여소만 출발지로 사용합니다. 목적지는 선택한 장소의 좌표입니다.
- 두 옵션이 모두 성공하면 API의 거리·소요시간과 각 `legs[].steps[].path.points`만 표시합니다. API 단계 사이를 임의 직선으로 연결하지 않습니다.
- 한 옵션이라도 인증 실패·권한 거부·호출 한도·타임아웃·경로 없음·잘못된 좌표 응답이면 비교 결과 전체를 비우고 이유를 표시합니다. 자동차 경로, 임의 곡선, 직선, 이전 예시 값으로 대체하지 않습니다.
- 대여소 또는 목적지가 바뀌면 이전 결과를 숨기고 진행 중인 브라우저 요청을 취소합니다.

실제 API 호출 권한을 검사하려면 프로젝트 폴더에서 실행합니다.

```bash
npm run test:kakao-routing
```

이 스크립트는 공식 예제의 공개 좌표로 두 옵션을 실제 호출합니다. 키·인증 헤더·원문 오류·전체 경로는 출력하지 않고 HTTP 상태와 성공 여부만 출력합니다. `.env.local`의 서버 키를 읽습니다. 키가 없으면 인증 없이 주소를 확인하되, **그 결과로 앱의 인증된 호출 권한을 판정하지 않습니다.**

최초 키 미설정 검사에서는 두 옵션이 HTTP 401을 반환했습니다. 이후 실제 키를 설정한 검사에서는 카카오 앱의 OPEN_MAP_AND_LOCAL 비활성화로 두 옵션이 403을 반환했습니다. 이는 당시 검사 결과이며 현재 상태는 `npm run test:kakao-routing`으로 확인하세요. 정상 경로를 수신하기 전에는 비교 수치를 생성하지 않습니다. 카카오모빌리티의 제휴용 자전거 API와 여기서 사용하는 카카오맵 REST API는 다른 주소입니다.

실사용에는 `.env.local`에 `KAKAO_REST_API_KEY`를 추가하고, 대여소 조회용 `SEOUL_API_KEY`와 지도 표시용 `NEXT_PUBLIC_KAKAO_MAP_APP_KEY`도 설정해야 합니다. 서버를 재시작한 뒤 권한 검사를 다시 실행하세요. 401은 인증키 확인, 403은 앱의 카카오맵 설정/권한 확인, 429는 호출 한도 확인이 필요합니다.

### 과거 자전거 사고다발지역

2026-11-19 확인한 [한국도로교통공단 공식 안내](https://opendata.koroad.or.kr/api/selectBicycleDataSet.do)는 자료조회 가능기간을 **2012~2025년**으로 명시합니다. 기본 사고 기준연도는 2025년이며 현재 연도나 API 조회 시각을 사고 연도로 사용하지 않습니다. `src/lib/accidents.ts`의 최근 제공연도·확인일은 이 문서를 근거로 관리하며 매 요청마다 문서를 자동 재확인하는 기능은 아닙니다. 새로운 연도가 공식 제공되면 해당 상수를 갱신해야 합니다.

실제 조회는 [공공데이터포털 API](https://www.data.go.kr/data/15056681/openapi.do)의 HTTPS 주소 `https://apis.data.go.kr/B552061/frequentzoneBicycle/getRestFrequentzoneBicycle`를 사용합니다. 서버에서 `serviceKey`, `searchYearCd`, `siDo=11`, 구별 `guGun`, `type=json`, `pageNo`, `numOfRows=100`을 전달합니다. 25개 구를 최대 3개씩 병렬로 조회하고 각 구의 모든 페이지를 수집합니다. 일부 지역/페이지 조회가 실패하면 불완전한 서울 목록을 정상 결과로 반환하지 않습니다. 정상 결과는 서버 메모리에 한 시간 보관합니다.

- `lo_crd`/`la_crd`의 실제 중심점과 `geom_json`의 실제 Polygon/MultiPolygon을 표시합니다. 폴리곤 구멍을 보존하고 임의 반경의 원이나 영역을 만들지 않습니다.
- 유효한 폴리곤이 없으면 중심점만 표시하고 그 사실을 카드에 안내합니다. 좌표가 없거나 잘못된 지역은 제외하고 `meta.skipped`에 집계합니다.
- 정상 조회된 **현재 선택 카카오 경로**와 각 사고영역 사이의 최소 지도상 직선거리를 미터 단위로 근사합니다. 선분 내부와 영역 교차도 검사하며 경로 단계 사이의 빈 구간을 연결하지 않습니다. 영역 안/교차는 0m입니다. 폴리곤이 없는 지역만 중심점과의 거리를 사용합니다.
- 근접 기준은 100/200/500m로 변경할 수 있습니다. 기본 200m는 앱의 근접 표시 기준이며 공단의 사고다발지역 선정 반경을 뜻하지 않습니다.
- 공식 경로가 없거나 조회 중/실패한 경우 근접 여부를 판단하지 않습니다. 실제 도로 연결·주행 방향·도로를 공유하는지·실제 통과 여부·실시간 사고 발생 위험도를 판정하는 기능은 아닙니다.
- `meta.year`는 요청한 사고 기준연도, `latestDocumentedYear`는 공식 문서에서 확인한 최근 제공연도, `yearCheckedAt`은 그 문서 확인일, `fetchedAt`은 서버 수집 시각입니다. 서로 다른 의미로 표시합니다.
- 선택 연도의 결과가 없으면 빈 결과를 표시하며 과거 연도로 자동 대체하거나 가상 데이터를 생성하지 않습니다. 공식 문서상의 2025년 제공 안내와 인증된 API의 실제 데이터 수신 성공은 구분합니다.

**과거 사고 통계이며 현재 사고 발생·실시간 위험도를 나타내지 않습니다. 표시되지 않은 장소가 안전하다는 뜻도 아닙니다.** 연도·조회 상태와 관계없이 이 안내를 화면에 유지합니다. 출처는 한국도로교통공단/TAAS와 공식 링크를 함께 표시합니다.

키가 없으면 `/api/accidents`는 `503 TAAS_NOT_CONFIGURED`를 반환하고 화면에는 연결 안내를 표시합니다. `.env.local`에 해당 서비스 활용 승인된 키를 입력하고 서버를 재시작해야 실데이터를 볼 수 있습니다. 지도에는 기존 카카오 JavaScript 키, 경로 근접 표시에 필요한 실제 자전거 경로에는 기존 서울시/카카오 REST 키도 필요합니다.

### 출발지 기상청 단기예보

[기상청 단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do)의 `getVilageFcst`를 사용합니다. 기존 초단기실황(getUltraSrtNcst), 가상 기온·강수확률·미세먼지·맑음 UI는 제거했습니다.

- 출발 대여소가 선택되어 있으면 그 실제 좌표, 없으면 검색 출발지 좌표를 사용합니다. 출발지가 바뀌면 이전 표시를 비우고 요청을 취소한 뒤 새 좌표로 조회합니다.
- `src/lib/weather.ts`의 Lambert conformal conic 변환: 지구반경 6371.00877km, 격자 5km, 표준위도 30/60N, 기준 126E/38N, 기준 격자 (43,136), 가장 가까운 정수 격자로 반올림합니다. [기상청 공식 격자영역 자료](https://apihub.kma.go.kr/getAttachFile.do?fileName=%2820240305%29%EB%8F%99%EB%84%A4%EC%98%88%EB%B3%B4+%EA%B2%A9%EC%9E%90%EC%98%81%EC%97%AD+%EC%A0%95%EB%B3%B4.pdf)를 기준으로 합니다. 범위 nx 1~149, ny 1~253 밖이면 다른 위치로 대체하지 않고 422를 반환합니다.
- 발표 후보는 KST 02/05/08/11/14/17/20/23시입니다. 앱은 발표 후 10분의 여유를 두고 가장 최근 회차를 요청합니다. 새 회차가 아직 정상 빈 응답(03/0건)이면 **직전 1회차의 실제 예보**만 재시도하며 사용한 실제 발표시각과 대체 사실을 표시합니다. 인증/권한·네트워크·형식·부분 페이지 오류에는 이전 회차로 대체하지 않습니다.
- 페이지를 모두 읽어 발표시각과 요청 격자가 일치하는지 확인하고 TMP·POP를 **예보일자+예보시각**으로 묶습니다. 현재 이후 6시간 이내의 가장 가까운 완전한 시간 쌍을 선택합니다. 예를 들어 14:45 조회 시 15:00 예보가 있으면 그 쌍을 표시합니다. 서로 다른 시간이나 회차의 기온과 확률을 섞지 않습니다.
- 0°C·강수확률 0%는 유효한 값입니다. 누락값, 잘못된 범위, 과거 예보만 있는 결과를 0이나 예시 값으로 채우지 않습니다.
- 원본 예보 항목은 서버 메모리에 5분 보관하고 동시 요청을 합칩니다. 캐시를 사용해도 매 요청 시점에 미래 시간 쌍을 다시 선택합니다. 발표회차가 바뀌면 캐시 키도 바뀝니다. 응답 헤더는 계속 `no-store`이며 키가 든 URL을 디스크에 캐시하지 않습니다.
- 화면은 5분마다 재조회하며 수동 재조회도 지원합니다. 발표/예보의 ISO 시각은 `+09:00`, 표시는 Asia/Seoul(KST)입니다. 서버 수집 시각을 예보 발표시각으로 사용하지 않습니다. 강수확률은 선택한 격자·예보시각의 값이며 경로 전체의 날씨를 뜻하지 않습니다.

키는 기존 `.env.local`의 `DATA_GO_KR_SERVICE_KEY`를 사용합니다. 공공데이터포털에서 이 단기예보 서비스 활용 신청 후 발급받은 **일반 인증키(Decoding)**를 입력합니다. 기상청 API허브의 authKey와 혼용하지 마세요. 키가 없으면 `503 KMA_NOT_CONFIGURED`로 안내하고 수치는 비워 둡니다. 서버를 재시작한 뒤 화면에서 다시 조회하세요.

### Git 및 배포

작업 폴더와 프로젝트 모두 `.env*`를 Git에서 제외하고 값이 비어 있는 `.env.example`만 예외로 허용합니다. `node_modules`, `.next`도 제외합니다. 이 작업 폴더에는 현재 Git 저장소가 없어 기존 GitHub 업로드나 커밋 기록은 검사할 수 없습니다. 이미 외부에 올린 키가 있다면 Git ignore로 과거 기록을 지울 수 없으므로 해당 키를 폐기하고 재발급해야 합니다.

배포할 때는 호스팅 서비스의 서버 환경변수에 키를 설정합니다. `.env.local` 파일 자체를 업로드하거나 커밋하지 마세요. 환경변수 변경 후 서버를 재시작하고, 공개 JavaScript 키를 변경하면 다시 빌드하세요.

### 전체 앱 검수와 현재 제한

`npm run test:live`는 실행 중인 http://127.0.0.1:3000의 실제 API를 호출합니다. 대여소 거리순·대여 가능·빈 검색, 실제 경로, 사고정보, 날씨, 잘못된 입력, 두 로컬 주소의 지도 SDK 인증 응답을 검사하고 비밀 키/원문 응답 없이 `test-results/live-api-results.json`에 저장합니다. 권한 설정 때문에 막힌 항목은 passed가 아니라 blocked로 기록하고 종료 코드 1을 반환합니다. 브라우저의 지도 렌더링이나 모바일 화면을 검사하는 스크립트는 아닙니다.

이번 실제 검사에서 공공 API와 빈 검색·입력 오류는 통과했습니다. 카카오 장소 검색/자전거 경로는 앱 권한 거부, 지도 SDK는 도메인/서비스 인증 오류로 막혀 있습니다. 카카오 콘솔의 사용 설정과 SDK 도메인을 수정한 뒤 다시 검사해야 합니다. 앱 코드가 외부 앱 권한이나 등록 도메인을 변경하지는 않습니다.

수정한 문제: 예시 목록에만 머물던 출발/도착 검색을 실제 API에 연결, 검색 인증/권한/한도 오류 구분, 지도 인스턴스 재생성 방지와 갱신 시 사용자 뷰포트 유지, 선택 마커 포커스, 최단 경로 범례 색 일치, 경로 요청 취소 직후 응답의 로딩 고정 방지. 모바일은 16px 입력·44px 터치 영역·320/360px 좁은 화면의 줄바꿈/스크롤 규칙을 보완했습니다.

브라우저 접근 호스트가 없고 Safari 네이티브 제어가 시간 초과되어 **실제 데스크톱/모바일 화면 조작·스크린샷 검수는 수행하지 못했습니다.** SDK 모의 객체 테스트로 마커/폴리곤/경로/클릭·인스턴스 재사용을 확인하고, 검색 이벤트/오류/빈 상태는 격리된 컴포넌트 테스트로 확인했습니다. 이를 실제 브라우저 검수나 실제 경로 API 성공으로 간주하지 않습니다.
